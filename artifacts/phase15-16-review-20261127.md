## 3. Point-by-point

### 3.1 Secret handling — clean

| Requirement | Result | Evidence |
|---|---|---|
| key in `sessionStorage` | yes | `dashboard.js:19, 150-173` |
| sent as `Bearer` header | yes | `dashboard.js:181` |
| `credentials: "omit"` | yes | `dashboard.js:185` |
| never in a URL | yes — no `location`/`href`/`URLSearchParams` in the file | grep: 0 hits |
| never `localStorage` / cookie / indexedDB | yes — 0 hits for all three | grep |
| never logged | yes — 0 `console.*` calls | grep |
| DOM via `createElement`/`textContent` only | yes — 0 hits for `innerHTML`, `outerHTML`, `insertAdjacentHTML`, `document.write`, `eval`, `new Function` | grep |
| 401 genuinely drops the key | yes — catch calls `dropKey()` then `showAuth()` | `dashboard.js:562-569` |
| key cleared from the input after submit | yes | `dashboard.js:608` |

One residual risk worth naming in ADR-010 (not a defect in this change): the key sits
in **origin-scoped** storage. The dashboard is served from the same origin as `/app`
and the CSP-exempt `/docs` (`main.py:68`). Any script-execution bug on either of those
can read the admin key out of `sessionStorage`. If the admin key is meant to outrank
the chat UI, the console belongs on its own origin (separate port), not a separate path.

### 3.2 Number correctness — sound, two nits

- Deltas: first poll is `0` because `previous.* === null` (`:339-342`); a counter reset
  clamps to `0` via `Math.max(0, …)` rather than plotting a negative spike. Both correct.
- Cooldown: 1 Hz `tick()` rewrites every `[data-until]` node from its ISO timestamp
  (`:513-528`); expiry renders `recovering`, never a negative countdown.
- Stale: `lastLoad` updates only on **success**, and `tick()` flips the indicator to
  `Stale` after `STALE_MS = 45000` (`:21, :525-527`). A failed poll leaves the old
  figures on screen but labels them — which is the behaviour asked for.
- Polling pauses on hidden tabs (`:586`) and re-fires on `visibilitychange` when the
  reading is older than one interval (`:653-657`).

Nits:
1. **The tile note disagrees with the sparkline.** `index.html:71` says
   `since start` for Requests; the sparkline directly beneath it plots *per-poll
   deltas*. The JS header comment claims the note says "since page opened"
   (`dashboard.js:10-13`) — it does not. Either label the sparkline ("last 40 polls")
   or drop it.
2. **Sparklines have no zero baseline.** `drawSpark` scales to the series' own
   min/max (`:284-291`), so a flat zero and a flat three render identically. A
   trend line that cannot distinguish "no traffic" from "steady traffic" is decoration.

### 3.3 Design critique — blunt

The craft is real: system type, one accent, tabular numerals, a genuine second dark
palette (not an inversion), and stated-preference handling for reduced motion,
reduced transparency and increased contrast (`css:728-777`). That is better than most
internal dashboards.

Where it is weak:

1. **It is derivative.** Sticky blurred topbar + four KPI tiles with sparklines +
   two-column card grid + pill states is the Apple/Linear dashboard template. The only
   SabiRoute-specific element on the page is the logo mark (`index.html:15-21`).
   Swap the wordmark and it could be any metrics product.

2. **It never answers the one question an operator has at 2 a.m.** "Is the gateway
   healthy right now?" requires reading four tiles, then a five-column table, then a
   latency table, and reconciling deployment names by eye between two separate cards
   (`index.html:112-122` and `:133-142`). *Fix:* one verdict strip under the topbar —
   `6/6 available · 0 failures in last 15 s · p50 640 ms` — built from data already
   fetched. One line, no new endpoint.

3. **Two bar idioms for one idea.** The health reliability `track` (`css:633-660`) and
   the latency/usage `row-meter` (`css:545-560`) are the same primitive drawn twice,
   at 5px and 3px, with different fills. Unify.

4. **Mobile tables will clip.** At `max-width: 560px` the only change is reduced
   padding (`css:711-715`). The health table has five columns with `white-space: nowrap`
   on the numeric ones (`css:528`) and no scroll container — on a 360px phone it
   overflows the card. *Fix:* wrap tables in `.table-scroll { overflow-x: auto }`, or
   drop Successes/Failures below 560px.

5. **Small grey text fails contrast.** `--text-3: #8a8a8f` on the `#f5f5f7` canvas is
   ≈ **3.15:1** — below WCAG AA 4.5:1 for normal text. It is used for the 11px table
   headers (`css:504-508`), 11px tile notes (`css:396-397`) and 12px card subtitles
   (`css:486-491`) — exactly the labels read at 2 a.m. Dark mode is fine (~6.9:1).
   *Fix:* darken to about `#6e6e73` (already defined as `--text-2`).

6. **Blur everywhere is expensive.** Five `backdrop-filter` layers over a fixed radial
   gradient (`css:85-88, 114-116, 377-378, 462-463`) repaint on every 15 s poll. The
   reduced-transparency path exists, but the default should not need it.

## 4. Defects ranked

**1 — High. Phase 16 status divergence between CLAUDE.md and README/build-map.**
`CLAUDE.md:300` still says `Planned`; `README.md:340` and `build-map.md:145` say
`Implemented`. The repo's own rule (`CLAUDE.md:311-312`) requires both to be corrected
together. Fix in the same commit as the status change.

**2 — Medium. `docs/admin-dashboard.md` is stale in a way that matters.**
It is the cited evidence for Phase 15 Complete, yet it names a different page title, a
different button label, a storage key that no longer exists (and was already misspelled),
and a 401 wart the new code fixes. An auditor following README row 15 is misled.
Rewrite the file against `web/dashboard/*`.

**3 — Medium. Health table has no overflow container; numeric columns are `nowrap`.**
`css:495-529` + `css:700-724`. Five columns at ≤560px will clip on a phone. Add
`.table-scroll { overflow-x: auto; -webkit-overflow-scrolling: touch }` around both
multi-column tables, or hide the two count columns below the breakpoint.

**4 — Medium. `--text-3` fails AA on the light canvas (≈3.15:1)** on the smallest,
most-read labels (`css:18, 504-508, 396-397, 486-491`). Use `--text-2` (`#6e6e73`,
≈4.9:1) for these, or darken `--text-3`.

**5 — Low. Concurrent `load()` has no in-flight guard** (`dashboard.js:542-579`).
Refresh click, the 15 s interval and `visibilitychange` can overlap; two responses then
compute deltas against the same `previous` and double-push into the sparkline, and the
first completion's `setBusy(false)` re-enables Refresh while the second is still running.
Add `if (loading) return;` / a sequence token.

**6 — Low. Tile note vs sparkline window mismatch** (`index.html:71` vs `dashboard.js:10-13,
347-355`). The note describes the cumulative number, not the plotted deltas, and the
JS comment claims a string that is not in the markup.

**7 — Low. `formatRemaining` at exactly 60000 ms** renders `1m 0s left` rather than
`60s left` or `1m`. Cosmetic.

**8 — Info. `autocomplete="off"` on a `type=password` field is widely ignored** by
browsers (`index.html:53`); `autocomplete="new-password"` is more likely to suppress the
save-password prompt for a credential that is deliberately tab-scoped.

**9 — Info. `scripts/phase15_browser_verify.py:90` binds via `SABIROUTE_P15_HOST`
without `resolve_bind_host`.** Test harness only, but it is a second, ungated bind path.

## 5. Bottom line

The build does what it claims. The loopback gate is real, enforced at the single
product bind site, and refuses `0.0.0.0`, a LAN address and a tailnet `100.x` without
the opt-in. The console never puts the admin key in a URL, a cookie, `localStorage`, a
log, or markup; it drops it on 401; it renders only through `textContent`. The delta,
cooldown and stale logic are correct, including the reset and first-poll edges. All
four gates are green.

It is **not** a slop template — but it is a very well-executed generic dashboard, and
the two things that would make it a *SabiRoute* console are missing: a single
at-a-glance verdict, and one merged deployment table instead of two.

The blocking follow-up is documentation, not code: fix the Phase 16 row in `CLAUDE.md`
§11 and rewrite `docs/admin-dashboard.md` against the shipped UI. Both are currently
misleading in exactly the way this repository says it does not tolerate.
