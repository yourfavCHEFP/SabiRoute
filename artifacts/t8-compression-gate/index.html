Decisive finding

The config-only adoption path cannot reach SabiRoute

The preflight identified the vendored interception logger as “a second seam.” It is one — but it is gated to a call type SabiRoute never issues, which rules out the cheapest option on the table. This is the finding the review decisions turn on. 

async def async_pre_call_deployment_hook(
    self, kwargs: dict[str, Any], call_type: CallTypes | None

    if not self.enabled:

        return None

    compressed = await asyncify(compress)(...)   # offloaded to a thread

litellm/integrations/compression_interception/handler.py:137–157

SabiRoute's entire provider surface is two OpenAI-shape calls — chat_completion and start_chat_completion_stream (litellm_client.py:71, :133) — and there is no Anthropic code anywhere in src/. Setting litellm_settings.compression_interception_params in config/config.yaml would therefore install a callback that returns None on every request the gateway actually serves.

The challenge

Three positions, one recommendation

ruled out

Adopt via proxy callback

Turn it on in litellm_settings with no SabiRoute code. Blocked by the anthropic_messages guard: a no-op on the gateway's only call path.

recommended

Wrap litellm.compress()

Call the function directly at the verified seam, offload it off the event loop, and keep policy, preservation and telemetry inside SabiRoute. Reuses shipping BM25 stubbing and token accounting without inheriting the call-type guard.

not advised

Build a new engine

The packet's original CD3 shape. Reimplements stubbing, relevance scoring, a retrieval cache and a savings ledger that the declared dependency already provides.

The recommendation is to wrap, and the reason is narrower than preference: litellm.compress() already returns original_tokens, compressed_tokens, compression_ratio, a retrieval cache and a compression_skipped_reason (litellm/types/compression.py:15–22) — which is most of the CD4 contract, already implemented, at no new dependency cost. Wrapping keeps that and still lets SabiRoute own the decisions CD4 reserves: when to run, what to preserve, and what to record.
