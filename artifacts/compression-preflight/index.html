Two interactions the packet does not name. Eight gates, eight open. The packet's central inventory claim survives: there is no compression code in this repository, no prior work to preserve, and the gateway has a clean, single seam where a transform can be inserted without touching routing, credentials or endpoint selection. Nothing was built.

What revalidation adds is the reason not to proceed straight to implementation. LiteLLM already ships relevance-based stubbing at the same seam, so the first design question is build versus adopt, not engine internals. Alongside it sit two omissions: a 300-second deadline that a compressor will spend from, and a telemetry contract asking for identifiers the event does not emit. All three are decisions for T8.
