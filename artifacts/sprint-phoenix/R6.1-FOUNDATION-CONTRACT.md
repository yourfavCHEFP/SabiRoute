## 3. THE FIVE REQUIREMENTS, STATED AS CONTRACT

**1 · Immutable original.** `FrozenOriginal` is a deep-frozen copy — a new list of new dicts,
not a shallow copy of the client's. The current client shallow-copies (a STATIC-ANALYSIS
FINDING in the source). Byte-equality pre/post is a test, not an assumption.

**2 · Canonical representation.** `CanonicalRequest` is deterministic and idempotent: the same
input yields the same bytes, and canonicalising twice changes nothing. It **never expands** —
output ≤ input. Unsupported shapes fail closed to `CanonicalisationError`, which is
fail-to-original, not a 4xx.

**3 · Metadata.** `TransformationRecord` carries ids, versions, counts, hashes and
`fallback_reason`. **It never carries text.** It is a frozen tuple, read-only to the API.

**4 · Policy and capability checks precede transformation.** I5 loads once at startup and is
frozen — a mid-request flip would split one reservation across two requests. I6 reuses the
existing capability enum and hard-fails to original if a transform would drop a required
capability. **Classification keeps reading the original**, so eligibility decided at `:1166`
is not invalidated by a later transform.

**5 · Explicit bypass.** `BypassDecision` is immutable per request, evaluated once, default-off.
A malformed caller signal is **ignored** in favour of the operator default — it never errors.

### D1 — the I2 budget is a value, and it is configurable

`OptimizationPolicy` carries `latency_budget_ms = 150.0` and `byte_budget_ratio = 1.25`
(`src/sabiroute/config/validation.py`), both validated and both settable at construction and
at load. **Neither is per-route overridable** — `RouteOptimizationOverride` carries no such
fields, unlike `max_ratio`. The pipeline enforces both
(`src/sabiroute/request_transform/pipeline.py`): a transform that exceeds either degrades to
the original through I9.

**Two limits on this, recorded rather than papered over:**

1. **The byte budget cannot bind *with the shipped compressor*.** It *can* bind at HEAD, and
   on any expansion it is the **first** gate to fire — measured, and asserted by
   `test_i2_an_expanding_transform_never_reaches_the_provider`. What is true is narrower:
   `compress()` only ever *removes* messages (`compression.py`), so the shipped path cannot
   produce an expansion for the budget to catch. It is kept so it binds if a rewriting
   transform is ever added, and it is tested directly (`within_byte_budget`) where it is
   genuinely falsifiable.
   *v2 said "cannot bind at HEAD" and justified it by a 1.0× canonical check that was, at the
   time, a tautology — see the repair note below. Both halves of that sentence were wrong.*
2. **The latency budget is a per-request ceiling, not a p95.** A p95 is a distribution over
   requests and cannot be enforced inside one request. What is enforced is a ceiling on the
   synchronous stall of the transform stage — the quantity §4 says the I2 budget measures.
   The p95 remains a **measurement to be taken in R6.2's benchmark**, not a gate this
   document can claim.

### D2 — `max_ratio` is 0.50 over 0.25..1.0, and an unreachable ceiling passes through

### D1 repair — the I2 canonical gate was a tautology

Not a departure but a defect found by review and fixed here. The pipeline's I2 non-expansion
check read:

```python
original_bytes = canonical_bytes(original)
canonical = original_bytes
if not within_budget(original_bytes, canonical):   # len(x) <= len(x)
```

`canonical` **was** `original_bytes`, so the check reduced to `len(x) <= len(x)` and the raise
was unreachable. The documented invariant — canonical bytes are never longer than the input's
**default JSON** (`canonical.py:8`) — was enforced nowhere on the pipeline path. It now compares
against the default encoding, which is the baseline the invariant actually names, and is
therefore falsifiable. Measured: `R6.1-REVIEW-RECORD.md` `[M] 6`.
