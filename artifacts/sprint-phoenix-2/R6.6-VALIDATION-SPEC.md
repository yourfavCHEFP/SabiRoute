# R6.6 VALIDATION AND EVIDENCE SPECIFICATION

**Issued:** 2026-11-17 · **Authority:** Row D authorises specification only.

## 1. Purpose

R6.6 defines what evidence would prove the request-transform pipeline works. This document
specifies; it does not run validation, call a provider, create a staging environment, or produce an
acceptance verdict.

---

## 2. Authority levels

| Level | Authority | What it can prove |
|---|---|---|
| L1 unit | controlled replay | Individual contracts I1–I9 fail closed when violated |
| L2 integration | controlled replay | The API path sends the effective request and preserves fail-to-original |
| L3 benchmark | controlled replay, fixed fixture | D1 budgets under a representative workload |
| L4 live observation | external service | Real provider behaviour — **not authorised** |
| L5 acceptance | owner | R8 acceptance — **BLOCKED** |

Only L1–L3 are in scope. L4 and L5 require separate named authority.

---

## 3. Evidence required before R6.6 could be called complete

1. **I1–I9 mutation matrix.** For each contract, a test that fails when the enforcing line is
   removed or inverted. Existing tests cover the contracts; the matrix must record the mutation
   result, not merely assert that a test exists.
2. **Dark-path byte equality.** At `enabled=false`, the provider payload is byte-identical to the
   pre-R6 path at both the transform boundary and the HTTP boundary.
3. **D1 latency.** `p95 ≤ 150 ms` and `≤ 1.25×` input on a fixed, versioned corpus. The policy is
   configurable; the benchmark must record the configuration used. The two budgets are global, not
   per-route overridable.
4. **D2 compression.** `max_ratio=0.50`, accepted range `0.25..1.0`. A request that cannot reach the
   ceiling without removing a protected message or splitting a tool exchange is sent unmodified.
5. **I9 cancellation.** `CancelledError` propagates; ordinary exceptions degrade to the original
   and are classified from the captured exception.
6. **Manifest and static gates.** `pytest`, `ruff`, `mypy`, `git diff --check` and the 13-entry
   manifest all reproducible at the cited SHA.
