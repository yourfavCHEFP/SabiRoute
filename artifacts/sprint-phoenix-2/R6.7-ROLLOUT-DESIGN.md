# R6.7 STAGED ROLLOUT DESIGN

**Issued:** 2026-11-17 · **Authority:** Row D authorises design only.
**Status:** DESIGNED · NOT DEPLOYED

---

## 1. Purpose

R6.7 describes how the pipeline could be enabled after R6.6 evidence exists. This is a design
record. No stage below is authorised to run; no staging environment exists; no flag may be flipped.

---

## 2. Default state

`OptimizationPolicy.enabled = False` at every layer. A per-route override cannot enable the global
pipeline; the two D1 budgets are global and not per-route overridable. The kill switch is the same
flag: setting `enabled=false` restores the pre-R6 path byte-for-byte on the next request.

---

## 3. Stages

| Stage | Population | Gate to advance | Rollback |
|---:|---|---|---|
| 0 | Test fixtures only | R6.6 L1–L3 evidence recorded at a cited SHA | Not applicable |
| 1 | Internal allowlist, one route | 24h of controlled-replay evidence; no capability-loss fallback above baseline | Set `enabled=false` |
| 2 | One low-risk route, 5% | p95 and byte-ratio budgets within D1 on fixed corpus | Set `enabled=false`; no data migration |
| 3 | Multiple routes, 25% | No uplift in `TRANSFORM_ERROR`, `CAPABILITY_LOSS` or `VALIDATION_FAILURE` | Per-route disable, then global disable |
| 4 | General availability, 100% | Owner acceptance recorded — R8 must no longer be BLOCKED | Global disable; original path unchanged |

---

## 4. Stop conditions

Any of the following halts advancement:

- a capability-bearing message is dropped;
- I9 degrades to `TRANSFORM_ERROR` above the recorded baseline;
- latency or byte budget exceeds D1 on the fixed corpus;
- the provider receives bytes that are not a monotone shrink of the original;
- a cancellation escapes the transform boundary incorrectly;
- the registration ledger is required to explain a result — it is permanently gated.

---

## 5. Rollback and kill switch

Rollback is a configuration change, not a code deployment. Because the original is frozen before
transformation and every failure path returns that original, `enabled=false` restores the exact
pre-R6 payload. No state migration, ledger write or cache invalidation is part of rollback.

---

## 6. Non-goals

No deployment, staging environment, provider call, push, R8 acceptance, T1/T8 verdict, or ledger
instantiation is authorised. R8 remains BLOCKED per D5 and the scorecard.
